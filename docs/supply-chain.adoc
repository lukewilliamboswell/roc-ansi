= Verify the source bundle

The release workflow generates supply-chain evidence for the exact Roc source
bundle it publishes. Releases before 0.13.3 do not carry this evidence. Keep the
bundle and its evidence together when admitting roc-ansi into your own build.

== What the evidence covers

From 0.13.4, each source bundle has these sidecars:

* `<bundle>.spdx.json`: SPDX 3.0.1.
* `<bundle>.spdx-2.3.json`: SPDX 2.3 for compatibility with existing consumers.
* `<bundle>.cdx.json`: CycloneDX 1.7, from the same inventory.
* `<bundle>.sbom-manifest.json`: Blueprint's manifest binding the SPDX 3.0.1
  and CycloneDX sidecars to subject bytes and inventory.

GitHub stores build-provenance attestations for the tested release files,
including these sidecars. The shared release workflow signs them; the source
is this repository's `main` at the release commit. The inventory, archive-member
list, evidence envelope and `.sigstore.json` bundles are not release assets.

The source inventory is independent of a CPU target. It covers the shipped
first-party modules and their declared UPL-1.0 license. Archive membership and
bytes are checked against the committed package source. Every bundled module
carries the copyright and license notice; the release also supplies `LICENSE`.
The recipe verifies that Roc reports no external package dependencies and
refuses that claim if the dependency closure changes.

The compiler is a build dependency, identified by its version and actual
executable SHA-256. Its native dependency closure is explicitly incomplete;
this source inventory does not establish a complete compiler/toolchain
inventory or the composition of an executable compiled downstream. The examples,
API archive and PDF are separate deliverables with their own provenance;
this source SBOM does not describe their contents.

== Verify a release before using it

Select the bundle filename from the GitHub release. Its Roc content-hash name
and its SHA-256 are different identities: use the SHA-256 in the SBOM to check
the delivered archive bytes. The shared workflow revision below is the one
reviewed for 0.13.4; review a later release's workflow pin before changing it.

[source,sh]
----
repo=lukewilliamboswell/roc-ansi
version=0.13.4
bundle='<bundle filename from the release>'
commit=$(gh api "repos/$repo/commits/$version" --jq .sha)
automation=2f8bd90acbfba5b1e6e8a50a0ba3c29a7816f25d
signer=lukewilliamboswell/roc-automation/.github/workflows/release-package.yml

gh release download "$version" --repo "$repo" \
  --pattern "$bundle" --pattern "$bundle.spdx-2.3.json" \
  --pattern "$bundle.sbom-manifest.json" \
  --pattern "$bundle.spdx.json" --pattern "$bundle.cdx.json"

for asset in "$bundle" "$bundle.spdx-2.3.json" \
  "$bundle.sbom-manifest.json" "$bundle.spdx.json" "$bundle.cdx.json"; do
  gh attestation verify "$asset" --repo "$repo" \
    --signer-workflow "$signer" --signer-digest "$automation" \
    --source-ref refs/heads/main --source-digest "$commit" \
    --deny-self-hosted-runners || exit 1
done

expected=$(jq -r '.packages[] | select(.SPDXID == "SPDXRef-Subject") | .checksums[] | select(.algorithm == "SHA256") | .checksumValue' "$bundle.spdx-2.3.json")
actual=$(shasum -a 256 "$bundle" | cut -d ' ' -f 1)
test "$actual" = "$expected"
----

Read the coverage statements as well as verifying signatures. Keep your own
admitted copy, expected signer policy and verification results. A signature
binds the bytes to the producer; the declared source coverage still needs review.

== Legacy evidence in 0.13.3

Release 0.13.3 also published the resolved inventory, archive-member list,
evidence envelope and two retained `.sigstore.json` bundles. It used this
repository's own release workflow and supplied a separate SPDX composition
attestation. Its verification commands and expected signer are preserved in
https://github.com/lukewilliamboswell/roc-ansi/blob/0.13.3/docs/supply-chain.adoc[the 0.13.3 verification guide].

== Chain into your own inventory

Preserve roc-ansi's immutable source location, release version, bundle SHA-256,
license and upstream document identity. Import the verified supplier graph,
including its coverage gaps. Pin the consumed file by SHA-256 and bind the
supplier SBOM to that exact artifact; checking only the SBOM's own checksum does
not bind it to a package. Keep build-only dependencies distinct from included
code and from dependencies fetched later.

Blueprint 0.8 accepts a source supplier into source and native inventories,
while preserving its `source` identity and checking exact supplier hashes and
versions. Native architecture compatibility checks remain strict. The regression
fixture in `tests/supply-chain/blueprint-source-import/` covers source-to-source,
source-to-Linux-x86_64 and source-to-Linux-arm64 admission, plus integrity refusals.
Keep source archives as build inputs and describe the resulting executable's
included code/assets and native closure separately.
